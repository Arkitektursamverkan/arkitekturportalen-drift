Om manualen och installationen

Arkitekturportalen är ett verktyg för verksamhetsarkitektur: processer, applikationer, information och teknik i ett gemensamt landskap med vyer, rapporter och analyser. Den installeras på organisationens egen server och körs där.

Installationen är en enda fil, arkitekturportalen-0.4.0.run, som laddas ner från GitHub. Filen innehåller allt som behövs. När den körs ställer den ett antal frågor, och sedan installerar och startar den portalen. Det tar normalt 5–15 minuter.

Manualen är till för att ni ska kunna förbereda svaren i förväg. Varje fråga förklaras i två rutor:

I korthet

Vad frågan gäller och vad de flesta svarar. Räcker för att komma igång.

Fördjupning

Vad svaret påverkar tekniskt, vilka alternativ som finns, vad som går att ändra senare och vad IT-avdelningen behöver veta.

Vad händer när filen körs?

  1. Den kontrollerar att Docker finns, och erbjuder att installera det annars.
  2. Den packar upp sig och läser in programmet i Docker.
  3. Den ställer frågorna i nästa avsnitt.
  4. Den skapar alla lösenord och nycklar som systemet behöver internt, startar portalen, skapar administratören och läser in exempelinnehållet.
  5. Den visar adressen till portalen och hur ni loggar in.
Allt går att ändra. Körs installationsfilen igen på samma server startar frågorna om med era tidigare svar ifyllda. Organisationens namn, e-postdomäner, moduler och läsning utan inloggning kan dessutom ändras i portalen under Administration → Organisation.

Det här krävs

Portalen körs på Linux. Det går bra med en virtuell server i organisationens befintliga miljö (VMware, Hyper-V, Azure, AWS m.fl.) eller med en fysisk dator.

Inloggning

Två sätt, som går att kombinera:

  • Microsoft Entra ID (tidigare Azure AD): medarbetarna loggar in med sina vanliga jobbkonton. Kräver en appregistrering som er Entra-administratör skapar före installationen (se fråga 5).
  • Lokala konton: en administratör i portalen skapar konton med e-post och lösenord. Inget behöver förberedas.

Installationsfilen

Filen laddas ner från github.com/Arkitektursamverkan/arkitekturportalen-drift under Releases. Den är ca 420 MB. Så länge portalen inte är publik krävs att ni är inloggade på GitHub med ett konto som Arkitektursamverkan (Halmstads Fastighets AB) har bjudit in.

Exempel: Ubuntu Server och Ubuntu Desktop

Två vanliga sätt att komma igång. Ubuntu Server är för den riktiga installationen, Ubuntu Desktop för att prova portalen på en vanlig dator.

Ubuntu Server – skarp drift

Ingen grafisk miljö; man arbetar via fjärranslutning (SSH). Det är så IT-avdelningar normalt driftar tjänster.

  1. Ordna en server med Ubuntu Server 24.04 LTS enligt tabellen på föregående sida.
  2. Be om DNS-namn som pekar på serverns adress, och öppna port 80 och 443 i brandväggen.
  3. Ladda ner filen från GitHub på din egen dator.
  4. Kopiera den till servern, t.ex. med WinSCP (Windows) eller: 
    scp arkitekturportalen-0.4.0.run anvandare@server:
  5. Logga in på servern och kör filen: 
    ssh anvandare@server
sudo sh arkitekturportalen-0.4.0.run
  6. Svara på frågorna (nästa avsnitt). Välj certifikat auto eller egen.

Har servern Ubuntus brandvägg påslagen släpper du igenom webbtrafiken med sudo ufw allow 80,443/tcp.

Ubuntu Desktop – prova på

En vanlig dator med grafisk miljö. Portalen nås bara från datorn själv, på adressen https://localhost.

  1. Installera Ubuntu Desktop 24.04 LTS, gärna i en virtuell maskin (t.ex. VirtualBox) med minst 4 GB minne.
  2. Ladda ner filen från GitHub i webbläsaren på den datorn. Den hamnar i mappen Hämtningar.
  3. Öppna Terminal (sök på "Terminal" i programmenyn) och skriv: 
    cd ~/Hämtningar
sudo sh arkitekturportalen-0.4.0.run
    Heter mappen Downloads skriver du det i stället.
  4. Svara på frågorna. Värdnamn: localhost. Certifikat: intern. Inget Entra ID; skapa ett lokalt administratörskonto.
  5. Öppna https://localhost i webbläsaren. Den varnar för certifikatet; välj Avancerat → Fortsätt. Det är väntat med ett internt certifikat.

Andra program på datorn får inte redan använda port 80 eller 443, annars stannar installationen när portalen ska starta.

Om lösenordet: när terminalen frågar efter lösenord (för sudo eller för administratörskontot) syns inget medan du skriver. Det är normalt – skriv lösenordet och tryck Enter.

Frågorna i installationen

Frågorna kommer i den här ordningen. Den mörka raden visar hur frågan ser ut på skärmen. Ett förslag inom hakparentes, [så här], väljs om man bara trycker Enter. (J/n) betyder att Enter blir ja, (j/N) att Enter blir nej.

1

Portalens värdnamn

Portalens värdnamn (DNS pekar på den här servern):
I korthet

Adressen användarna skriver i webbläsaren för att nå portalen, utan https://.

Skarp drift: t.ex. arkitektur.kommunen.se
Test på egen dator: localhost
Fördjupning

Namnet måste finnas i DNS och peka på serverns IP-adress innan portalen används, annars når ingen den. Be er nätverks- eller DNS-ansvariga lägga upp en A-post (eller CNAME).

Namnet används på tre ställen: av webbservern för att svara på rätt adress, i certifikatet och som tillåten adress för inloggningen. Med Entra ID ska samma adress finnas som omdirigerings-URI i appregistreringen.

Byter ni namn senare: kör filen igen med det nya namnet och uppdatera appregistreringen i Entra.

2

TLS-läge (certifikat)

TLS-läge:   auto · egen · intern
I korthet

Hur portalen får sitt certifikat, så att anslutningen är krypterad (hänglåset i webbläsaren).

auto – servern nås från internet
egen – ni har ett eget certifikat
intern – test och slutna nät
Fördjupning

auto: certifikat hämtas gratis från Let's Encrypt och förnyas automatiskt. Kräver att servern nås från internet på port 80 och 443 under värdnamnet. Följdfråga: en e-postadress som får varningar om certifikatet inte kunnat förnyas.

egen: organisationens certifikat, t.ex. från er interna CA eller en köpt leverantör. Lägg certifikatfilen (med hela kedjan) och nyckelfilen i katalogen /opt/arkitekturportalen/certs/. Följdfrågor: filernas namn (förslag fullchain.pem och privkey.pem). Saknas filerna väntar installationen tills de finns. Ni ansvarar själva för att byta certifikatet innan det går ut.

intern: portalen skapar sitt eget certifikat. Fungerar direkt men webbläsarna varnar tills ni låter datorerna lita på det. Bra för test, inte för en tjänst många ska använda.

Fördjupning

Frågan ställs bara för valda moduler som har exempel:

Modulerna, Integrationsplattformen och Arkitekten

Kärnan ingår alltid. Modulerna väljs i fråga 8 och kan slås på och av senare. Integrationsplattformen väljs i fråga 9 och Arkitekten i fråga 10; båda är egna system som körs bredvid portalen.

Kärnan

Ingår alltid

Vad den gör

Arkitekturobjekten – processer, applikationer, informationsobjekt, informationskällor och teknikkomponenter – och sambanden mellan dem. Klickbara grafvyer för att utforska landskapet, ett tjugotal rapporter (t.ex. applikationsportfölj, överlapp och luckor, livscykel, teknisk skuld, NIS2 och behandlingsregister), lösningsskisser, import och export med CSV, samt administration av användare och behörigheter.

Vad det innebär

Det här är portalen. Den fungerar fullt ut utan några moduler. Innehållet fylls på för hand, med CSV-import eller automatiskt via Integrationsplattformen. Behörigheter kan sättas per objekt och grupp.

Verksamhetskalender

Modul

Vad den gör

En gemensam kalender för verksamhetens händelser och frysperioder – t.ex. bokslut, löneperioder och större driftsättningar – tillsammans med en förändringslogg över vad som ändrats i IT-landskapet.

Vad det innebär

Ger förvaltning och IT en plats att se när ändringar passar och inte passar. Administratören bestämmer vilka avdelningar som får skriva i förändringsloggen. Följer inget exempelinnehåll; kalendern fylls av organisationens egna händelser.

Samarbeten

Modul

Vad den gör

Arbetsytor för uppdrag och arbetsgrupper. Varje yta har egna sidor, mötesanteckningar från mallar, uppladdade filer, en diskussionstavla, uppgifter och en kalender, och en egen medlemslista.

Vad det innebär

Behörigheten gäller per yta: ägare, medlem eller läsare. En yta är privat som standard. Uppladdade filer (högst 25 MB styck) lagras i portalens databas och följer med i backupen – tänk på diskutrymmet om mycket laddas upp.

Arkitekturstyrning

Modul

Vad den gör

Arkitekturprinciper och principdokumentet, nulägesanalys, målarkitektur och GAP-analys med handlingsplan. Dokumenten kan skrivas ut som PDF.

Vad det innebär

För organisationer som arbetar med arkitekturstyrning och vill ha principer och målbild på samma ställe som landskapet. Exempelpaketet ger en stomme att utgå från.

Ordlista

Modul

Vad den gör

Organisationens begrepp med definitioner, och ett sätt för användarna att föreslå nya begrepp.

Vad det innebär

Ger ett gemensamt språk för arkitekturarbetet. Exempelpaketet innehåller grundbegrepp inom verksamhetsarkitektur.

Enkäter

Modul

Vad den gör

Enkäter till användarna, t.ex. om systemnöjdhet eller arkitekturmognad. Användarna besvarar dem under Mina enkäter, och resultatet publiceras som rapporter.

Vad det innebär

Varje publicerad omgång blir en egen rapport under Rapporter, så att resultat kan jämföras över tid. Följer inget exempelinnehåll; enkäterna skapas i portalen.

Förändringsstatistik

Modul

Vad den gör

En rapport över hur arkitekturen förändras: tillagda, uppdaterade och borttagna objekt per BDAT-lager och objekttyp mellan två datum, med grafer att borra ned i, filter och export till CSV.

Vad det innebär

Räknas ur revisionsloggen, så statistiken börjar när portalen började användas. Med modulen på sparas objekthistoriken även när revisionsloggen töms.

Integrationsplattformen

Eget system bredvid portalen – fråga 9

Vad den gör

Hämtar uppgifter från andra system – SharePoint-listor, processmodeller i 2C8, REST-API:er och CSV-filer – bearbetar dem i flöden och lämnar dem till portalen. Flödena körs på schema, t.ex. varje natt, eller när någon trycker på Hämta nu i portalen.

Har ett eget webbgränssnitt för anslutningar, flöden, scheman och körningsloggar.

Vad det innebär

  • Mindre handpåläggning: applikationslistan och processerna hålls i takt med källsystemen.
  • Eget DNS-namn och mer minne och processor på servern.
  • Inloggningsuppgifter till källsystemen lagras i plattformen, krypterade. Nyckeln finns i .env – utan den blir de oläsbara, ytterligare ett skäl att spara filen säkert.
  • Nätverk: servern måste nå de system som ska läsas.
  • Kan läggas till senare genom att köra installationsfilen igen.

Arkitekten (processritaren)

Eget system bredvid portalen, kräver Integrationsplattformen – fråga 10

Vad den gör

Ritar affärsprocesser och systemprocesser med versioner: ett utkast blir fastslaget när det är klart. Fastslagna processer som publiceras till portalen visas på processkartan och, för systemprocesser, under fliken Systemprocesser hos applikationen.

Har ett eget webbgränssnitt och en länk från portalens toppfält.

Vad det innebär

  • Bilderna går via plattformen: plattformen hämtar dem från Arkitekten varannan timme, eller när någon trycker på Hämta nu. Därför kräver Arkitekten plattformen.
  • Eget DNS-namn och egen inloggning (Entra ID eller egna konton).
  • AI-stödet är valfritt och använder en egen nyckel till Anthropic.
  • Processerna ligger i en egen volym och ingår i backup.sh.
  • Kan läggas till senare genom att köra installationsfilen igen.

Efter installationen

Logga in

Öppna portalens adress. Med Entra ID loggar de administratörer ni angav in med sina jobbkonton; annars loggar ni in med det lokala administratörskontot. Gå sedan till Administration för att bjuda in fler och justera inställningarna.

Backup

Installationen tar inga backuper av sig själv. Lägg in en nattlig backup – IT-avdelningen kan göra det med kommandot sudo crontab -e och raden:

0 3 * * * cd /opt/arkitekturportalen && ./backup.sh >> backups/backup.log 2>&1

Backuperna hamnar i /opt/arkitekturportalen/backups/ på samma server, och de 14 senaste sparas. Kopiera dem regelbundet till en annan plats. De innehåller nycklarna och ska förvaras som lösenord.

Uppgradera till en ny version

Ladda ner den nya installationsfilen från GitHub och kör den på samma sätt som första gången. Den känner igen den befintliga installationen, tar en backup och startar den nya versionen. Inga frågor ställs om utom en bekräftelse. Skulle något gå fel skriver den ut hur ni kommer tillbaka till läget före.

Ändra svaren

Kör samma installationsfil igen. Frågorna kommer med era tidigare svar som förslag; tryck Enter för att behålla dem. Befintliga lösenord, nycklar och data behålls.

Avinstallera

Ska portalen bort från servern: ladda ner arkitekturportalen-avinstallation.run från samma ställe som installationsfilen och kör den på samma sätt:

sudo sh arkitekturportalen-avinstallation.run

Den visar vad som är installerat och erbjuder en sista backup, och att spara backuperna utanför installationen så att portalen kan återskapas senare. Inget tas bort förrän ni har skrivit avinstallera. Sedan tas portalen, all dess data och programmet bort; Docker finns kvar. DNS-namnen, appregistreringen i Entra ID och brandväggsöppningarna tas bort för hand.

Om Arkitektursamverkan och Arkitekturportalen

Bakgrunden. Arkitekturportalen började som ett eget behov hos Halmstads Fastighets AB (HFAB). Vi gjorde en kartläggning av vår IT-arkitektur – processer, system, information och teknik – med TOGAF som ramverk i bakhuvudet. Kartläggningen behövde ett hem där den kunde hållas levande och användas, inte bara ett dokument som blir inaktuellt.

Valet. Vi utvärderade olika systemstöd för arkitekturarbetet. Slutsatsen blev att det var värt att pröva att utveckla ett eget, med hjälp av AI-agenter. Resultatet är Arkitekturportalen och Integrationsplattformen.

Delningen. Vår vision är att släppa portalen som öppen källkod – den är redan licensierad under EUPL-1.2, EU:s licens för fri programvara. Eftersom vi inte har arbetat så här tidigare börjar vi försiktigt: de som är intresserade bjuds in att ta del av koden via GitHub under namnet Arkitektursamverkan. Vi hoppas kunna dela den fullt ut publikt framöver, och att fler organisationer vill vara med och utveckla den.
